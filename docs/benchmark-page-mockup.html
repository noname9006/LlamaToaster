Sizes are per KV token relative to f16/f16. The unquantized pair is mandatory — it is the only one that can also run with flash attention off, so the FA axis collapses without it. The two middle pairs decompose K-path from V-path cost. V is compressed harder than K, never the reverse: errors in K pass through a softmax that can amplify them, while errors in V are averaged and smooth out. A1b

The first three ETAs come from this machine’s own llama-bench history. The last two don’t: nothing has measured llama-server prompt processing on toaster-01, and the engine-to-engine gap has never been re-measured since single-slot mode landed — published figures span 300 to 1 700 tok/s. Rather than pick one, the stage says so. P4.2

P6.4“Recommended” must not mean opaque. Each stage card is a disclosure button; opening one shows exactly what it will run, pre-filled and editable. Fields sit in three tiers — varied, held constant (each carrying its reason), and required (each carrying its consequence). Only three fields in all of Test A are genuinely required, and they all sit on the sweep stage.
P6.4A loaded preset is applied verbatim, across any machine. Re-deriving on load would quietly turn a saved configuration into a different one; instead the disagreement is surfaced per field with the machine’s own value one click away. The advisory VRAM banner does the safety work, so nothing has to be taken away from the user to keep this safe.
P3.1Unknown header fields are the launch-day default, not an edge case — the GGUF is parsed at download time only, and every model registered before v7 has none of it. The card is designed for that state first.
P3.2The banner states a confidence word, not just a number. “rough” and “good” must never look alike — a gating check built on a rough estimate would silently delete valid data points.
A1bThe default KV cache set spends its four slots deliberately: one baseline that can also run flash-attention off, two that decompose K-path cost from V-path cost, and one asymmetric-aggressive pair — never the reverse asymmetry, since K errors pass through a softmax that can amplify them.
A4Test A is three stages, all llama-bench. Chaining is justified only where a stage’s grid is derived from the previous stage’s results — which is true here and nowhere else. Test B is a separate trigger; folding it in as stages 4–5 would run it twice for anyone who also used the profile dropdown, and would ask the user to commit to the expensive half before anything could price it.
P6.1The handoff is a completion call to action, not an automatic enqueue. By then the sweep has measured rates, so the offer carries an estimate instead of a shrug.
P0.4Sweep size is a count, not a clock — the per-test time limit is a different thing entirely (Screen 2). Past 4 096 tests the request still succeeds with a warning; the hard rejection is at 20 000, high enough not to break sweeps that work today.
P2.4Stop is chain-scoped by construction: it sets a flag on the root, which is what stops stages that don’t exist yet.

2 · Test B — what the user will actually experience

A separate trigger, enabled once Test A has produced profiles. Everything here is already known the moment those profiles exist, so Test B needs no chaining at all — one run per selected profile, all enqueued together, sharing a root for grouping and Stop. This screen only exists because v7 splits mtp into an engine/spec pair; until then there was no way to ask for llama-server without speculative decoding, which is the entire measurement this test is about.

3 · Runs — one trigger, one row

Test A is three runs in the database and Test B is up to three more. The two tests group separately — different roots, different engines — linked by the profile the second one names.

What this changes about the current UI

New route /benchmark, two tabs

/new-run stays exactly as it is and becomes Test A’s Expert mode. Existing bookmarks keep working; the sidebar entry is renamed.

“Budget” split into two words

Sweep size is a count of tests. Per-test time limit is a clock. Calling both “budget” is how an earlier draft came to compare a whole column’s runtime against a per-test timeout and conclude that runnable work was impossible.

Recommended values are visible and editable

Every stage opens into an editor pre-filled with what it will run. Held-constant fields say why they’re pinned; the three genuinely required ones say what breaks. Reset re-derives from the machine rather than restoring page-load values.

Presets are yours, not a machine’s

Listed on every machine you own, with no hardware filtering, and loaded verbatim — nothing silently re-derived. Where a saved value differs from what this machine would pick, the editor says so and offers the swap. Taking it is your decision.

Two tests, two triggers

Test A chains three llama-bench stages and ends at three profiles. Test B is started separately from one of them and needs no chaining — its runs are all determined up front. The drainer exists for Test A alone.

Runs list groups by root

One expandable row per trigger, with stage pips, one aggregate progress figure, one ETA, one Stop. Cursor pagination lands with it — this multiplies the row count 6×.

Skipped becomes a visible outcome

Hollow dashed ring, its own count in every summary, a reason on hover, and no effect on whether a run reads as done.

Every estimate is labelled

KV size carries a confidence word. TTFT carries measured-vs-derived. Speedup carries ok / unverified. Nothing presents a guess in the same visual register as a measurement — and where nothing has been measured, the field says unavailable rather than extrapolating.

Unknown metadata is a designed state

Header fields are parsed at download time only, so every model registered before this work has none of them. That is the launch-day default, not an edge case, and it gets a card layout and a repair action rather than a row of dashes.

Profiles say what they didn’t measure

Speed and memory only — no perplexity, no accuracy proxy, no column for one. A Low Memory card recommending a 4-bit KV cache carries that boundary in its own copy, because the launch command beside it reads as advice.

Run detail gains a chain rail

Stage breadcrumbs across the top, so a sub-run is never orphaned from the thing it belongs to.

Accessibility bar, stated

Stage pips have text alternatives, stage transitions announce politely, the sweep grid is keyboard-navigable, profile cards are a radio group, mismatched options use aria-disabled so their reason survives.
