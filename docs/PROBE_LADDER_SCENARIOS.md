# LlamaToaster — Probe Ladder Scenarios

Companion to [BENCHMARKING_PLAN_V8.md § N2](BENCHMARKING_PLAN_V8.md) and the
search engine in [`shared/probeLadder.ts`](../shared/probeLadder.ts). That
file's own header covers the design ideas; this file enumerates every branch
the search can actually take, for someone debugging a real `probe_attempts`
trace against what the code *should* have done — one section per Benchmark
page card, `basic` and `fine` each, plus Custom (which has no granularity
split), for eleven scenarios total.

Card copy (name + description) is pulled verbatim from
[`GoalQuestionnaire.tsx`](../client/src/components/GoalQuestionnaire.tsx) so
this doc reads the same as the UI.

Every trace below is **generated by running the real engine**, not derived by
hand. Regenerate them after any change to the engine rather than patching a
table — see the fixture section for the exact inputs.

---

## Vocabulary

| Term | Meaning |
|---|---|
| `nglMax` | Total layer count of the model — "every layer on GPU". |
| your own `(ngl, ctx)` | Whatever the layer/context sliders are set to when you hit Test — `placement.ngl` / the live `ctx` value. |
| precalc (ngl) | `estimateSafeNgl` at the phase's pinned context — the pre-flight safe-layer-count guess. |
| precalc (ctx) | `maxAffordableContext` at the phase's pinned layer count — the pre-flight safe-context guess. |
| stop | One of `ctxLadderStops`' pure power-of-two values: `1024, 2048, 4096, 8192, ...` up to the model's own trained-ctx ceiling (always included exactly, even off-grid). Every ctx-axis phase, at both granularities, only ever tests these plus (under `fine`) values strictly between two adjacent ones. |
| bracket | Once one **success** and one **failure** are both known on an axis, bisection narrows the mean of those two real, already-tested values — never a value beyond either. |
| grow ceiling | `bestNglAtContext` — the most layers whose *estimate* still affords the context a phase has already pinned. Every "now add layers" phase grows toward this, never toward `nglMax`. Pure estimate evaluations, zero loads. |
| back-off | `max_gpu` only: giving layers back once its context has collapsed to the floor. See that card's section. |

## Quick reference

| Card | Mode | Phase 0 | Phase 1 | Later | basic vs fine |
|---|---|---|---|---|---|
| **Max GPU speed** | `max_gpu` | `ngl`, seed = `nglMax`, direct-jump-to-precalc on failure, ctx pinned at the floor | `ctx`, seed = nearest stop to precalc | phases 2+3 **only if phase 1 stayed below the second stop**: give back the fewest layers that let `2048` load, then re-walk ctx from there | phase 0 identical; phase 1: `fine` refines past where `basic` stops |
| **Max context** | `max_context` | `ctx`, seed = nearest stop to precalc, pinned at `bestNglForMaxContext`'s answer (searched for, **not** the user's own `ngl`) | `ngl`, seed = **that same pinned `ngl`** (reused, no load), grows toward the grow ceiling, never gives back ctx; **skipped entirely** when the ceiling is the seed | — | phase 0: `fine` refines past `basic`; phase 1 identical |
| **Fixed context** | `keep_context` | `ngl`, seed = your own `ngl`, direct-jumps to the grow ceiling on success or to precalc on failure | *(none — ctx never moves)* | — | **byte-identical at both granularities** — `ngl` has no tolerance/granularity split |
| **Balanced** | `balanced` | `ctx`, seed = nearest stop to your own `ctx` | `ngl`, seed = your own `ngl` (reused, no load), grows toward the grow ceiling; skipped when there is none | — | phase 0: `fine` refines past `basic`; phase 1 identical |
| **Fixed offload** | `fixed_offload` | `ctx`, seed = nearest stop to your own `ctx` | *(none — ngl never moves)* | — | `fine` refines past `basic` |
| **Custom** | `custom` | one load at exactly your `(ngl, ctx)` | *(none)* | — | identical — no search at either granularity |

### The ctx axis

Every ctx-axis phase, in every mode, runs the SAME two-stage engine
(`nextSliderRefineCandidate`):

1. **Walk the stop ladder** one notch at a time from the seed — up on
   success, down on failure — until the walk reverses (an adjacent
   success/failure pair). That's `basic`'s complete answer.
2. **`fine` only:** refine *within* that specific bracket via ordinary
   bisection, down to a minimum step of **1/16 of the bracket's own width**
   — fixed once, from the literal stop pair stage 1 found, never
   recomputed smaller as the bisection narrows further.

### The ngl axis

No grid — every integer layer count is individually selectable, so
`basic`/`fine` never differ here. Two rules shape it:

- **The grow direction is bounded by the estimate, not by `nglMax`.** After a
  ctx phase has pushed context to a placement's real boundary, the layer
  counts between the seed and `nglMax` are precisely the ones that cannot
  fit; bisecting that range spends the whole remaining budget proving it.
  `bestNglAtContext` names the highest layer count the estimate still affords
  at the pinned context, and that becomes the phase's grow target. When it
  equals the seed, a pure grow phase (`max_context` / `balanced` phase 1) is
  **skipped outright** — zero loads, not five failures.
- **Trusted targets are jumped to, not halved toward** (`nextDirectCandidate`).
  `max_gpu`'s layer phase jumps to the safe-ngl estimate on its seed's first
  failure; `keep_context` jumps to whichever of its two targets the seed's
  verdict points at; `max_context`/`balanced` phase 1 jumps to the grow
  ceiling. Once the target itself has been tried, all of them fall back to
  ordinary bracket bisection between real, tested values.

**Load budget:** `PROBE_MAX_LOADS` defaults to **24**, admin-configurable at
runtime under **Platform settings → Probe max loads** on the admin dashboard
(delivered to workers on their ~10 s heartbeat, and enforced independently
server-side when results are reported).

## What a probe actually stores

Worth knowing before reading a verdict, because two things changed here and
both are easy to misremember:

- **The context is stored exactly as loaded, not snapped to a stop.** A
  `fine` search converges *between* two stops; snapping that down at storage
  time always landed back on the lower stop `basic` had already found, which
  made every extra `fine` load incapable of changing the stored number by
  construction. `snapToSafeCtx` still exists and is still "down, never up" —
  it now runs where a slider value is genuinely needed, when you click a card
  to **apply** it. So a `fine` card can legitimately report `43,008` and
  apply `32,768`; the tables below name both.
- **The ceiling is filed under the placement it was VERIFIED at.** The ladder
  moves `ngl` in every mode but Fixed offload and Custom, so the layer count
  the probe finishes at is routinely not the one it was requested with — for
  Max GPU speed the requested one is `nglMax`, which is usually the very
  first rung to fail. The worker reports `verified_ngl` alongside the
  context, and `model_machine_limits.placement_hash` is keyed on it (a worker
  predating the field falls back to the requested placement, as before).

Clicking a tested card applies **what the probe proved** — its verified
`(ngl, ctx)`, context snapped down — not the values it started from.

## Worked-example fixture

Every table below except the Real-model section runs the same synthetic model
through the actual `nextLadderRung` engine, so the numbers are computed:

```
nglMax = 48, trained ctx = 262,144            -- matches shared/probeLadder.test.ts
your own placement: ngl = 16, ctx = 32,768
true fit rule:      ctx × (ngl + 4) ≤ 900,000 -- a stand-in VRAM budget
calculateNgl():     always 26                  -- a deliberately imperfect
calculateCtx(ngl):  1.25 × the TRUE boundary      pre-flight estimate, same
                                                   as the unit tests use
```

The true ctx boundary at `ngl=16` is `floor(900000/20) = 45,000`; the
pre-flight estimate (`calculateCtx(16) = 56,250`) is deliberately 25 %
optimistic, so every trace below has to correct for a wrong estimate — the
same property the real unit tests hold the engine to. At `ngl=48` the true
boundary is `floor(900000/52) = 17,307`.

Two variant fit rules appear where the default one can't show a branch:

- **generous** — `ctx × (ngl + 4) ≤ 10,000,000`. Every layer fits at the floor
  context, so `max_gpu`'s layer phase converges in one load and its ctx phase
  gets room to run all the way through `fine`'s refine stage.
- **tight** — `ctx × (ngl + 4) ≤ 100,000`. Weights dominate: the layer phase
  wins layers the context phase then cannot use. This is the only fixture
  that triggers `max_gpu`'s back-off.

Under THIS fixture, `calculateCtx(ngl)` is strictly decreasing in `ngl` (more
layers on GPU always means a smaller ctx estimate — no dual-pool
non-monotonic bump), so `bestNglForMaxContext(48, calculateCtx) = 0` every
time: Max context's traces below all pin phase 0 at `ngl=0`, not the
placement's `ngl=16`. A real interior-peak case is covered in that section.

## Real-model example: `unsloth/gemma-4-12b-it-GGUF`, `UD-Q5_K_XL`, on an 8 GB / 32 GB machine

This section runs an actual model through the actual estimator
([`shared/vramEstimate.ts`](../shared/vramEstimate.ts)) and the actual ladder
end to end.

**Inputs.** Repo and file are real (HF's parsed GGUF metadata confirms
`context_length: 262144`). Architecture pulled from
`unsloth/gemma-4-12b-it`'s `config.json` (`text_config`):

```
num_hidden_layers        = 48   ->  totalModelLayers (this app's "+1" convention) = 49
hidden_size               = 3840
num_attention_heads       = 16
num_key_value_heads (kv)  = 8
head_dim                  = 256
max_position_embeddings   = 262,144
sliding_window            = 1024   -- present in the config, but see note below
file size (UD-Q5_K_XL)    = 8.61 GB  =  8,610,000,000 bytes
```

Machine: **8 GB VRAM GPU, 32 GB system RAM** — "some random" card, so a stated
assumption fills in what a spec sheet doesn't: ~490 MiB already claimed by the
desktop/driver, leaving **`freeVramMib = 7700`**. 32 GB RAM is never the
binding constraint anywhere in this example.

> **Note on `sliding_window`:** this app's GGUF parser
> (`worker/src/gguf.ts`) doesn't yet recognize a sliding-window key for the
> `gemma4` architecture, so `meta.sliding_window` comes back `undefined` for
> a real registered copy of this model today, and `calculateCtx` never enters
> `maxAffordableContext`'s sliding-window-aware branch — it uses the plain
> formula below instead.

> **Note on headroom:** `maxAffordableContext` defaults to reserving 10 % of
> `totalMib` for activations, but the worker passes
> `activationsHeadroomFrac: 0` because `freeVramMib` is *already* a free
> budget and stacking the two would double-apply it
> ([`worker/src/index.ts`](../worker/src/index.ts)). The numbers below are the
> worker's — call the estimator with its defaults and you will get smaller
> ones.

### Step 1 — `estimateSafeNgl` (the layer-phase precalc)

```
bytesPerLayer = 8,610,000,000 / 49 = 175,714,286 bytes  (~167.6 MiB)
usableBytes   = (freeVramMib − 512 fixed overhead) = 7188 MiB
safeLayers    = floor(7188 / 167.6) = 42
```

**precalc ngl = 42** out of 49.

### Step 2 — `maxAffordableContext` (the context-phase precalc), at a few candidate `ngl`

| ngl | weightsMib (`estimateVramNeededMib`) | estimate |
|---|---|---|
| 49 (every layer) | 8723 | **0 tokens**, `binding: "weights-placement"` — the weights alone already exceed the 7700 MiB budget |
| 42 (the Step 1 estimate) | 7550 | **0 tokens**, `binding: "weights-placement"` — closer, but weights + the 256 MiB scratch reservation still overrun by ~106 MiB |
| 38 (the layer phase's real verdict — see Step 3) | 6880 | **1504 tokens**, `binding: "kv"` |
| 36 (the back-off's verdict) | 6545 | **2397 tokens**, `binding: "kv"` |
| 16 | 3193 | **11,336 tokens**, `binding: "kv"` |

The lesson Step 2 makes concrete: **the layer-phase estimate (42) leaves zero
room for context** — `estimateSafeNgl` only ever subtracts a flat 512 MiB
overhead, never the scratch/headroom `maxAffordableContext` separately
reserves. This is exactly why the ladder searches instead of trusting the
first number: the two precalc estimates aren't mutually consistent.

A real `0` from `maxAffordableContext` is treated as the floor, not as the
trained ceiling. The old fallback (`tokens > 0 ? tokens : maxCtx`) inverted
"nothing fits here" into "everything fits here", which seeded context phases
at the top of the ladder and — worse — could make exactly the hopeless `ngl`
look like the best possible pin to `bestNglForMaxContext`. Only a
`confidence: "unknown"` verdict (no KV geometry to reason with at all) still
falls back to the caller's ceiling.

### Step 3 — the actual probe trace: Max GPU speed, `basic`

"True" pass/fail for this worked example = the same real functions above with
a stated **12 % real-world margin** (CUDA graph/scratch overhead the flat
estimator doesn't model) layered on top — the gap an actual probe exists to
catch.

| load | ctx | ngl | result | why |
|---|---|---|---|---|
| 1 | 1024 | 49 | FAIL | seed = every layer |
| 2 | 1024 | 42 | FAIL | **direct jump to the Step 1 precalc — not a midpoint** |
| 3 | 1024 | 21 | ok | precalc also failed → retarget toward 0: mean(42, 0) = 21 |
| 4 | 1024 | 32 | ok | bracket `[21 ok, 42 fail]` → mean 32 |
| 5 | 1024 | 37 | ok | bracket `[32 ok, 42 fail]` → mean 37 |
| 6 | 1024 | 40 | FAIL | bracket `[37 ok, 42 fail]` → mean 40 |
| 7 | 1024 | 39 | FAIL | bracket `[37 ok, 40 fail]` → mean 39 |
| 8 | 1024 | 38 | ok | bracket `[37 ok, 39 fail]` → mean 38 → **layer phase converges at ngl=38** |
| 9 | 2048 | 38 | FAIL | ctx phase begins: seed = nearest stop to `calculateCtx(38)=1504` → 2048 |
| 10 | 2048 | 36 | ok | ctx phase converged **at the floor** → back-off (phase 2): give layers back until 2048 loads |
| 11 | 2048 | 37 | FAIL | bracket `[36 ok, 38 fail]` → mean 37; gap to 36 is 1 → converged |
| 12 | 4096 | 36 | FAIL | phase 3: re-walk the ctx ladder from the proven 2048 → next stop up fails → converged |

The ctx phase's own walk down from 2048 to 1024 costs nothing: `(ctx=1024,
ngl=38)` was already loaded at load 8 (the layer phase pins ctx at the floor
the whole time it runs), and `nextLadderRung`'s history replay reuses that
verdict instead of spending a real load re-proving it.

**Verdict: `ngl = 36`, `ctx = 2048`** — two layers given back to double a
context that was otherwise pinned at the unusable floor. Without the back-off
this probe reported `ngl = 38, ctx = 1024`: nominally "more GPU", actually a
configuration nobody can run a conversation in.

## Max GPU speed (`max_gpu`)

> Every layer on the GPU, then as much context as still fits.

### `basic`

```
test nglMax (every layer), with ctx pinned at the floor
│
├─ ok ────────────────────────────────────────────► layer phase DONE at nglMax
│                                                     (converges in 1 load)
└─ FAIL
   │
   test precalc(ngl) directly ── NOT a midpoint toward it
   │
   ├─ ok  ─► bracket [precalc ok, nglMax fail] -- bisect the two real values,
   │          narrowing every step until the gap is ≤ 1 layer
   └─ FAIL ─► retarget toward the hard floor (0), same bracket logic

then, context phase:
stops = ctxLadderStops(trainedCtx)     -- [1024, 2048, ..., 262144]
seed  = nearest stop to precalc(ctx)
│
walk one stop per load, up on success / down on failure, until it reverses
│
└─ if that converged BELOW the second stop (2048), the layers won cost all
   the context -- back off:
      phase 2 (ngl, ctx re-pinned at 2048): give back the fewest layers that
              let 2048 load. Ceiling is one below the layer phase's answer,
              which phase 1 just proved fails at 2048.
      phase 3 (ctx): re-walk the ladder from the proven 2048 at that new ngl
```

**Real trace** (`gemma-4-12B`, `nglMax=49` fit outright, true ctx boundary
`≈ 260,000` out of a 262,144 trained ctx, precalc ctx `= 21,634` — the trace
that motivated this whole rework):

| load | ctx tested | result |
|---|---|---|
| 1 | 16384 | ok *(nearest stop to 21634)* |
| 2 | 32768 | ok |
| 3 | 65536 | ok |
| 4 | 131072 | ok |
| 5 | 262144 | FAIL *(the ceiling itself)* |

5 loads, all real stops. The **old** engine spent all 8 loads on
`1024, 131584, 196864, 229504, 245824, 253984, 258064, 260104` and still
hadn't converged.

**Fixture trace, default fit rule** (`nglMax=48` fits at the floor context, so
the layer phase converges in one load and the trace is all context work;
true boundary at `ngl=48` is 17,307):

| load | ctx | ngl | result |
|---|---|---|---|
| 1 | 1,024 | 48 | ok *(layer phase — seed is its own grow target, converges here)* |
| 2 | 16,384 | 48 | ok *(ctx phase — nearest stop to precalc 21,634)* |
| 3 | 32,768 | 48 | FAIL *(above the 17,307 boundary)* |

Verdict `ctx=16,384, ngl=48` — the highest stop at or below the true boundary.

**Fixture trace, tight fit rule** — the back-off case:

| load | ctx | ngl | result | phase |
|---|---|---|---|---|
| 1 | 1,024 | 48 | ok | 0 — every layer fits, but only at the floor |
| 2 | 16,384 | 48 | FAIL | 1 — ctx phase seeds high (the estimate is 1.25× optimistic) |
| 3 | 8,192 | 48 | FAIL | 1 — walk down |
| 4 | 4,096 | 48 | FAIL | 1 |
| 5 | 2,048 | 48 | FAIL | 1 — reverses against the reused `1024 ok`; converged AT THE FLOOR |
| 6 | 2,048 | 47 | FAIL | 2 — back-off begins, ctx re-pinned at 2,048 |
| 7 | 2,048 | 24 | ok | 2 |
| 8 | 2,048 | 36 | ok | 2 |
| 9 | 2,048 | 42 | ok | 2 |
| 10 | 2,048 | 45 | FAIL | 2 |
| 11 | 2,048 | 44 | ok | 2 — gap to the nearest failure (45) is 1 → converged |
| 12 | 4,096 | 44 | FAIL | 3 — re-walk ctx from the proven 2,048; next stop up fails |

Verdict `ctx=2,048, ngl=44` — four layers traded for twice the context,
instead of `ctx=1,024, ngl=48`.

### `fine`

Layer phase is identical to `basic` (no granularity split on the `ngl`
axis). Context phase runs the SAME walk `basic` does, seeded at the same
stop — the difference only shows up once that walk converges: `fine` keeps
going, refining within the final bracket down to 1/16 of that bracket's own
width.

## Max context (`max_context`)

> The largest context this machine can hold — the layer split is searched
> for, not taken from your sliders — then more layers if there's room.

The card renders its starting layers as `searched` rather than as a number,
because the sliders' own `ngl` genuinely does not decide it. Fixed offload is
the card for "hold my layer split"; this one is defined by not doing that.

### `basic`

```
PRE-STEP (bestNglForMaxContext, zero real loads -- pure calculateCtx() calls):
coarse step-2 climb from ngl=0 until the estimate stops improving, then a
step-1 refine BOTH directions from that coarse peak (the true, integer-
resolution peak can sit just past it, not only among the values coarse
skipped on the way up) -- this is what phase 0 pins to, NOT the user's own
ngl, and NOT assumed to be 0 either.

phase 0 (ctx): seed = nearest stop to precalc(ctx) AT THAT PINNED ngl
│
… same walk-then-(fine only)-refine engine every ctx phase uses …

phase 1 (ngl): seed = THE SAME pinned ngl from the pre-step -- already proven
               at phase 0's resolved ctx, so it is REUSED from history, never
               a fresh load
│
├─ grow ceiling (bestNglAtContext at the resolved ctx) == the seed
│     ─► NO PHASE AT ALL. The estimate says not one more layer affords this
│        context; spending five loads proving it is the exact failure mode
│        this check exists to prevent.
└─ otherwise ─► jump straight to the grow ceiling, then bracket-bisect
                between it and the seed. ctx never moves here, so this can
                only ever ADD layers, never trade context away for them.
```

**Fixture trace.** `calculateCtx` is strictly decreasing in `ngl` here, so
`bestNglForMaxContext` pins at `ngl=0` — not the placement's `ngl=16`.
`calculateCtx(0) = 281,250`, clamped to the 262,144 trained-ctx ceiling:

| load | ctx | ngl | result | phase |
|---|---|---|---|---|
| 1 | 262,144 | 0 | FAIL | 0 — nearest stop to the (clamped) estimate is the ceiling itself |
| 2 | 131,072 | 0 | ok | 0 — walk down one stop; converged |
| 3 | 131,072 | 4 | FAIL | 1 — grow ceiling at 131,072 is `ngl=4`; jumped to directly |
| 4 | 131,072 | 2 | ok | 1 — bracket `[0 ok, 4 fail]` → mean 2 |
| 5 | 131,072 | 3 | FAIL | 1 — bracket `[2 ok, 4 fail]` → mean 3; gap to 2 is 1 → converged |

Verdict: `ctx=131,072` at `ngl=2` — far more context than the fixture's true
45,000-token boundary at the placement's own `ngl=16` would ever allow, found
precisely because phase 0 searched for the best `ngl` instead of assuming it.
Growing toward `nglMax` instead of toward the estimate's ceiling took 7 loads
for this same verdict.

**A real interior peak** (the shared fixture can't show this — it's monotonic
by construction — so this uses a dedicated fixture: a tent function peaking
at `ngl=10`, `nglMax=40`):

```
bestNglForMaxContext(40, ngl => 40000 - |ngl-10|*500) = 10
```

Phase 0 pins there directly — not `ngl=0`, not the user's own `ngl` — and the
first rung `nextLadderRung` returns is already `ngl=10`, before any
context-axis load has been spent.

### `fine`

Phase 0 runs the same walk, then refines; phase 1 is identical at both
granularities.

| load | ctx | ngl | result | phase |
|---|---|---|---|---|
| 1 | 262,144 | 0 | FAIL | 0 |
| 2 | 131,072 | 0 | ok | 0 — walk converges: bracket `[131072 ok, 262144 fail]`, width 131,072, tolerance 8,192 |
| 3 | 196,608 | 0 | ok | 0 — refine: mean(131072, 262144) |
| 4 | 229,376 | 0 | FAIL | 0 — refine: mean(196608, 262144) |
| 5 | 212,992 | 0 | ok | 0 — refine: mean(196608, 229376) |
| 6 | 221,184 | 0 | ok | 0 — refine: mean(212992, 229376); gap to 229,376 is 8,192 ≤ tolerance → converged |
| 7 | 221,184 | 1 | FAIL | 1 — grow ceiling at this much larger ctx is `ngl=1`; one load closes the bracket |

Verdict: `ctx=221,184` at `ngl=0`, stored exactly, **applies as `131,072`**.
`fine` found substantially more context than `basic`'s `131,072` and gave up
the two spare layers to get it — but note that once applied, both land on the
same slider stop. Growing toward `nglMax` here cost 6 loads instead of 1, all
of them guaranteed failures.

## Fixed context (`keep_context`)

> Your context is fixed; the layer split moves to make it fit.

### `basic` and `fine` — byte-identical

```
one phase (ngl): seed = your own ngl
│
test seed
├─ ok ──► jump straight to the grow ceiling (bestNglAtContext at the pinned
│          ctx, never below the seed)
└─ FAIL ─► jump straight to precalc(ngl) at the pinned ctx
… once both a success and a failure exist, bracket-bisect the two real
  values directly, narrowing until the gap is ≤ 1 layer
```

There is no ctx phase — `granularity` never gets consulted here at all,
because `NGL_TOLERANCE` is a flat `1` regardless of `basic`/`fine` (unlike
the ctx axis, which always at least walks the stop ladder and, under `fine`,
also refines). **This is worth knowing before assuming a `fine` re-test of a
Fixed context card will ever produce a different number or cost a different
number of loads than `basic` did — it won't.**

**Fixture trace** (`ctx=32,768` pinned, `ngl=16` seed; grow ceiling at that
context is `ngl=30`; true boundary works out to `ngl=23`):

| load | ctx | ngl | result |
|---|---|---|---|
| 1 | 32,768 | 16 | ok *(seed)* |
| 2 | 32,768 | 30 | FAIL *(direct jump to the grow ceiling — not a midpoint toward `nglMax`)* |
| 3 | 32,768 | 23 | ok *(bracket [16 ok, 30 fail] → mean 23)* |
| 4 | 32,768 | 27 | FAIL *(bracket [23 ok, 30 fail] → mean 26.5 → 27)* |
| 5 | 32,768 | 25 | FAIL *(bracket [23 ok, 27 fail] → mean 25)* |
| 6 | 32,768 | 24 | FAIL *(bracket [23 ok, 25 fail] → mean 24)* |

Converges at `ngl=23`; gap to the nearest known failure (24) is 1 → done.

## Balanced (`balanced`)

> Starts where you are: more context first, then more layers if any still
> fit.

The old copy said "trades context against layers", which the search does not
do: phase 0 only moves ctx at your own `ngl`, and phase 1 only *adds* layers
at the ctx phase 0 resolved. Neither axis is ever given up to buy the other.
`max_gpu`'s back-off is the only phase in any mode that trades one for the
other, and it only does so to escape the floor.

### `basic`

Phase 0 seeds at the nearest stop to your own `ctx` (not the estimate) and
walks the ladder from there — so unlike Max context, this phase's seed
usually isn't already a bracket end.

**Fixture trace** (`ctx=32,768` — already a stop; true boundary at `ngl=16` is
45,000; grow ceiling at 32,768 is `ngl=30`):

| load | ctx | ngl | result | phase |
|---|---|---|---|---|
| 1 | 32,768 | 16 | ok | 0 — your own ctx, already a stop |
| 2 | 65,536 | 16 | FAIL | 0 — walk up one stop; converged |
| 3 | 32,768 | 30 | FAIL | 1 — jump to the grow ceiling |
| 4 | 32,768 | 23 | ok | 1 — bracket `[16 ok, 30 fail]` |
| 5 | 32,768 | 27 | FAIL | 1 |
| 6 | 32,768 | 25 | FAIL | 1 |
| 7 | 32,768 | 24 | FAIL | 1 — gap to 23 is 1 → converged |

Verdict: `ctx=32,768` at `ngl=23` — Balanced never got past the first ladder
stop above 32,768 (65,536 failed outright), so all its extra headroom over
the seed went into layers instead, landing well short of the 45,000 true ctx
ceiling (which Max context, seeded at the estimate instead, gets closer to).

## Fixed offload (`fixed_offload`)

> Your layer split is fixed; context moves to make it fit.

### `basic`

```
one phase (ctx): seed = nearest stop to your own ctx, at the pinned ngl
│

only difference from Balanced's phase 0 is there is no phase 1 (ngl is
```

## Branches that don't look like the tables

The traces above all end in a verdict. These don't, and are just as real:

- **Nothing fits at all.** When a phase's every rung fails, the ladder stops
  there rather than letting a later phase pretend to rescue it
  (`nextLadderRung` returns null), and `bestLadderResult` returns null. The
  probe reports `failed` — or `failed_oom` if any rung actually OOM'd — with
  no `verified_ctx_tokens`, and the card shows "✗ didn't fit". Every attempted
  rung is still written to `probe_attempts`; the evidence survives even
  though the ceiling doesn't.
- **`fine` that never brackets.** Refinement needs both a success and a
  failure among the *stops*. A walk that runs off the top (the trained-ctx
  ceiling itself loads) or off the bottom (even 1024 fails) has neither, so
  `nextSliderRefineCandidate` returns null and `fine` costs exactly what
  `basic` did. Don't read "same load count as basic" as a bug.
- **`fine` that brackets and gains nothing.** See Max GPU speed's default-fit
  trace: the boundary can sit anywhere inside the bracket, and when it sits
  just above the lower stop every refine step fails. The extra loads are the
  price of finding out, not a malfunction.
- **The budget running out mid-search.** `nextLadderRung` returns null the
  moment history reaches `maxLoads`, wherever that lands. The verdict is
  still whatever `bestLadderResult` finds among the rungs that did run — a
  real, loaded configuration, just not necessarily a converged one. Nothing
  in the report distinguishes "converged" from "ran out"; count the rungs
  against the live cap to tell.
- **A stray result on the wrong side of a proven value.** A flaky load, or
  another process taking memory mid-probe, can produce a failure below a
  known success. The bracket rules ignore it: only a failure *above* the best
  success, or a success *below* the worst qualifying failure, ever defines a
  bracket. The rogue rung stays visible in `probe_attempts` without steering
  the search.
- **Resuming from stored history.** The engine is stateless — it re-derives
  which phase each rung belonged to by replaying the same deterministic
  decisions against the history it is handed. Feed it a truncated
  `probe_attempts` list and it picks up exactly where that list stops, which
  is what makes a trace debuggable in the first place.

## Open scope decisions

The ctx-axis walk-then-refine engine (`nextSliderRefineCandidate`), the
estimate-bounded grow ceiling (`bestNglAtContext`), and Max context's ngl
pre-step (`bestNglForMaxContext`) are now used exactly where this doc
describes them. Direct-jump (`nextDirectCandidate`) is no longer `max_gpu`'s
alone — every ngl-axis phase in every mode now jumps to its trusted target
rather than halving toward it.

One asymmetry remains, deliberately:

- **The ngl priority-search** (`bestNglForMaxContext`) is intentionally
  `max_context`-only. `balanced` starts from where you are, and
  `fixed_offload`/`keep_context` are defined by holding your layer split;
  extending the pre-step to them would contradict what those cards promise.

And one known limit worth naming rather than hiding:

- **`max_gpu`'s back-off only reaches for the second stop (2048).** It gives
  back the fewest layers that let a context above the floor load, which is
  the right shape for a card whose whole promise is layers — but 2048 tokens
  is still small. A machine where the model genuinely needs a large CPU share
  will report a small context here and should be tested with Max context or
  Balanced instead. Widening the back-off's target would start turning Max
  GPU speed into Balanced, so it is left where it is.
